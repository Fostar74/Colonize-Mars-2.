# The Orange Empire Phase 1

## Integration

| Area | Existing integration | Phase 1 behavior |
| --- | --- | --- |
| Persistence and alliance | Human memberships and sessions reference `users`. | A singleton NPC alliance owns ten commanders in additive SQLite tables. Commander 10 is the Emperor. Each commander has its own position, clock, resources, jobs, army, unit upgrades, economy XP, Cyber Knight and protocols. |
| World map | `placedMapObjects` feeds player spawns and both mine allocators. The authenticated `/map/bases` endpoint feeds the map. | Seeded NPC positions participate in placement checks. Orange markers and a bilingual navigation list use a distinct NPC target type. |
| Economy | `src/shared/unitEconomy.js` provides unit prices, building requirements and durations, and training and upgrade data. The player runtime supplies the production cadence and the protocol catalog. | The NPC scheduler advances the economy every ten seconds. Paid jobs and production carry survive restarts. SQLite serializes seed and update transactions, and stored timestamps prevent crediting a tick twice. After downtime, production catches up through at most 24 hours and already paid jobs complete once. New jobs start at the current tick. |
| Levels and garrisons | The player level function caps at 40. Existing campaign garrisons provide encounter strength references. | All ten commanders now have a fixed campaign level of 45. The existing economy XP still progresses independently and unlocks command protocols. Preview garrisons use the existing campaign headcounts for tiers 11–20 with corresponding trainable units. Home armies have no march cap. The knight record starts at level 1. |
| Combat | The campaign timeline settles arrivals and returns in timestamp order. PvP settlement uses the shared battle engine, player protection, and per-player casualty and report writes. | Phase 2 uses the existing settlement timeline, formation rules, equipment bonuses, and hospital writes. Attack dispatch and combat require a separate opt-in. |

## Phase 2 combat

- Two dispatch slots per eligible player each UTC week open on Monday and Thursday. Repeat processing is safe, and the scheduler retries unused open slots while time and troops are available. It allows one unresolved incoming Orange Empire attack per player. Unused slots from previous weeks expire. A march canceled by protection at arrival still consumes its dispatch slot.
- Only level-40 humans can be targeted. Beginner protection and shields are checked at dispatch and again at arrival. Commanders are selected in ascending initial garrison order based on prior dispatches. When several players draw from one commander in a tick, the army is shared across their marches within the 50,000 population cap. A commander with no available troops waits. Surviving troops return to the commander at the same speed.
- For the Emperor gate, Phase 2 treats a claimed alliance station as the built alliance base. A station enters the target pool when its spaceport is building or built. Station attacks use the eligible leader's weekly slot and require station ownership, current leadership and station protection to pass validation. The leader's stationed army defends alongside the first three arrived, current allied garrisons. Existing station deployments beyond those slots remain stationed.
- Home defense uses the player's entire home army and up to three allied contingents per march. The authenticated map lists incoming attacks and lets allies send troops before arrival. Each group uses its owner's formation, unit upgrades, and combat bonuses. Wounds go to the troop owner's hospital and surviving support troops return to their owners. Existing alliance deliveries continue to use their existing rules.
- Each map tile takes five minutes in either direction, using the existing PvP distance rule where a diagonal counts as one tile. Loot, reconnaissance, mine targeting, final names and additional knight progression are outside this phase.

## Migration and rollback

The server creates the NPC and combat tables on startup. With `ORANGE_EMPIRE_ENABLED` unset or any value other than `true`, seeding, progression and map exposure are disabled. Set it to `true` only on a test instance with a persistent SQLite path to preview the faction. Seed placement and all ten inserts commit together. If there is insufficient room, the transaction rolls back and the scheduler logs the error.

Phase 2 requires both `ORANGE_EMPIRE_ENABLED=true` and `ORANGE_EMPIRE_ATTACKS_ENABLED=true`. Both default off and the production configuration leaves them unset. Turning off the attack flag stops dispatch and cancels unresolved marches at arrival, returning troops on their normal return schedule. Disable the main feature and restart to hide the preview while retaining progress and map reservations. Re-enabling resumes from the stored clock with the same catch-up limit. Keep the tables during a version rollback to retain a recovery copy. A version predating this change does not reserve NPC tiles, so restore or reconcile those positions before re-enabling if any bases or mines were placed while running that version.
